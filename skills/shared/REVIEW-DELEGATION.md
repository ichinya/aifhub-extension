# Specialized support for an existing review

Use when an authorized review has separable concerns that benefit from independent attention and the host offers permitted read-only subagents. The coordinating parent owns dispatch, complete coverage and the combined verdict. Small reviews stay direct; a delegated sidecar never launches nested reviewers. Missing subagents retain the ordinary review path and must not be reported as independent review.

## Bind the scope before dispatch

Keep the user's selected comparison semantics and resolve its exact base/target. Include relevant uncommitted and added files through identified snapshots and the full selected patch; HEAD alone is insufficient. Bind canonical requirements, applicable standards and accepted policy snapshots to the same target. Do not replace a requested working-tree review with a merge-base comparison or silently choose a different spec.

Give each support assignment one concrete question, allowed context and tools, the exact target and expected coverage. Examples include whether a changed permission path enforces the existing rule, whether a migration preserves supported callers, or whether a test reaches the reported defect. Read relevant unchanged callers when needed within the permitted scope. Pointers are usable only when the receiver can read them; otherwise supply permitted source excerpts with their identities and limitations. A sidecar without a shell must not claim executed Git or checks.

## Preserve the two passes

First complete plan/spec compliance. Reconcile missing, extra or contradicted behavior before moving to code quality. Independent supporting questions within that pass may run concurrently. Then assess correctness, regressions, security, performance, maintainability and test quality as warranted by the changed scope. A later quality result cannot erase a compliance finding.

Support workers return observations and findings with target-specific locations, requirement/rule basis, impact and coverage gaps. They do not write artifacts, dispatch workers, change tracker state or issue a separate final gate. Use a support assignment compatible with those permissions; do not override a packaged full-review sidecar's required output contract to repurpose it. A packaged full-review sidecar retains its two passes and existing final result format.

Distinguish a documented violation from a design heuristic. A possible code smell without a concrete consequence is not automatically a defect or a mandate to refactor. Existing project standards and accepted decisions govern the task; do not import a universal smell checklist or require cosmetic cleanup.

## Reconcile coverage and findings

The parent inspects each returned finding against the pinned source and reconciles all assigned questions, including missing answers. Resolve conflicting reports from evidence; keep distinct defects distinct and merge duplicates only when they describe the same cause and impact. Keep existing finding IDs for re-review and preserve unresolved blockers. A count, majority vote, green test command or empty worker report is not coverage evidence.

If a source changed, refresh only the affected review work against an explicit current target. If requirements are unavailable, report the compliance gap rather than inventing a specification or inferring it solely from the patch. Complete missing coverage directly when permitted; otherwise do not return PASS for the requested complete scope. Retain FAIL for known blockers and WARN for incomplete evidence without a known blocker, using the existing result schema.

Return one combined findings-first verdict in the caller's existing format, identifying the reviewed scope and material limitations. Preserve `/aif-review` read-only boundaries, scoped re-review rules, project-required independent review, `/aif-verify` and `/aif-done` ownership. Specialist participation alone creates no fresh-context receipt and proves no cost or quality improvement.
