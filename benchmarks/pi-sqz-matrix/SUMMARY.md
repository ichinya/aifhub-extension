# Pi × SQZ live matrix — когда context-dedup с SQZ полезен, а когда вреден

Эксперимент по мотивам issue #186. Агент **pi** (print mode), провайдер
**omniroute**, модель **`la/ornith-1.5-35b-a3b`**, thinking `low`. Три
независимых прогона × 6 анонимизированных репозиториев × 2 типа задач × 3 arms
(`off` / `aifhub` / `sqz`) = **108 прогонов**.

Reads перехватываются расширением `dedup-read.mjs` и прогоняются через боевой
`scripts/context-dedup.mjs` (тот же контракт: `sqz compress --no-cache`,
session ledger для точных повторов, fail-open, protected artifacts).
Состояние изолировано per-run; после каждого exec-прогона рабочее дерево
восстанавливается снапшотом. Метрики: model-visible байты (extension) и
измеренный provider usage (pi session files). Стоимость токенов провайдером
не предоставляется → `unavailable`.

Репозитории обезличены метками стеков: `laravel-php`, `flutter-dart`,
`unity-csharp`, `react-typescript`, `python-ts-monorepo`, `fastapi-react`.

## Главный результат

**Экономия байтов ≠ экономия токенов.** SQZ стабильно сжимает 25–72%
model-visible байтов, но в 4 из 6 профилей **увеличивает** полный расход
токенов: сжатый код токенизируется в 3–5 раз хуже несжатого, и агент
компенсирует потерю структуры дополнительными чтениями и поворотами.

### Exec-задачи (точечные правки, средние in+out)

sqz дороже off в 5 из 6 профилей: laravel-php 8 702 → 14 505 (2 валидных
прогона, третий — ERROR агента), react-typescript 10 951 → 17 030,
python-ts-monorepo 8 719 → 14 980, unity-csharp 8 921 → 12 444.
Единственная exec-экономия — flutter-dart (11 188 → 9 631, −14% при 74.4%
сжатия), выборка мала. Файлы в exec-задачах малы (~2–4 KB): сжатие не
окупает оверхед поворотов. AIFHub-arm в exec нейтрален (кривая совпадает с off).

### Дедупликация на живых сессиях

За 108 прогонов: `aifhub` — **0** точных повторов (агенты pi не перечитывают
неизменённые файлы в одной сессии), `sqz` — 12 replay-хитов и 44
compression-reads, 0 предупреждений (`§ref`/`§delta`, timeout, unavailable не
встретились). Dangling references не зафиксированы.

## Когда включать

### Матрица решений по меткам (sqz против off, 3 прогона)

| метка | research | exec (точечные правки) | решение |
|---|---|---|---|
| `laravel-php` | ✅ −35% | ❌ +67% | включать для research-сессий; для правок — off |
| `fastapi-react` | ➖ −4% | ➖ +1% | экономии нет, держать off (включение безвредно) |
| `react-typescript` | ❌ +97% | ❌ +56% | не включать |
| `python-ts-monorepo` | ❌ +46% | ❌ +72% | не включать |
| `unity-csharp` | ❌ +127% | ❌ +39% | не включать |
| `flutter-dart` | ❌ +208% | ⚠️ −14% (74.4% сжатия) | не включать для research; exec — только после доп. повторений |

Качество ответов по меткам от arm не зависит (кроме дефектного сценария
flutter-dart research — см. ниже), решение принимается целиком по стоимости.

1. **Laravel / PHP-домены — подтверждённый сценарий.** Research по
   laravel-php: −35% токенов при 3/3 качестве; плотные текстоёмкие файлы
   (doc-блоки, конфиги, шаблоны) сжимаются с сохранением токенизируемости.
   Для точечных правок в тех же репозиториях сжатие не окупается — держать
   `minBytes` по умолчанию.
2. **Мультирепо-оркестрации — безопасно, но решать per-repo.** Session ledger
   и sqz-home изолированы внутри корня каждого репозитория, перекрёстных
   ссылок между репо нет по конструкции (подтверждено юнит-тестами изоляции
   сессий; прямых live-замеров мультирепо не проводилось). Правило: для
   каждого репозитория свой профиль — текстоёмкие (Laravel/доки) включать,
   кодовые (C#/Dart/TS-исходники) выключать.
3. **Длинные сессии с гарантированными повторными чтениями** — режим для
   `mode: aifhub` без sqz: ничего не сжимает, повторы обслуживает replay-маркером.

## Когда не включать

- **Code-exploration по исходникам C#/Dart/TS** — байтовые «65–72% savings»
  превращаются в +97–208% расхода токенов.
- **Точечные правки** почти во всех профилях.
- **Репозитории из мелких файлов** — `minBytes` отсекает (fastapi-react:
  1.8% сжатия; включение бессмысленно).

## Качество

- Assert-провалы сгруппированы в одном сценарии (слишком строгий факт
  `ProjectsRepositoryException`): flutter-dart research off 0/3, aifhub 1/3,
  sqz 1/3 — дефект сценария, не инструмента.
- Остальные различия — единичные промахи без связи с сжатием.
- Execution-верификация: правки корректны во всех PASS-прогонах; рабочие
  деревья возвращены в baseline (остаточных правок нет).
- 1 разовый краш агента помечен ERROR и не засчитан ни в качество, ни в экономию.

## Ограничения

- 3 повторения на клетку, один агент, одна модель, один раннер; доверительные
  интервалы широкие, выводы опираются на агрегаты по профилям.
- Токены — measured provider usage; стоимость задачи — `unavailable`.
- Перехватывается только `read`; bash/grep-чтения не дедуплицируются.
- Одна платформа (Windows); linux-прогоны не выполнялись.

## Вердикт (bounded)

- **Включать**: текстоёмкие репозитории (Laravel/PHP — измеренный выигрыш),
  длинные сессии с повторами.
- **Выключать**: code-exploration по компилируемым исходникам (C#/Dart/TS),
  короткие правочные задачи.
- **Мультирепо**: включение безопасно (изоляция per-repo), решение принимать
  отдельно для каждого репозитория по его контенту.
- Универсальное «экономит до N%» не подтверждается: N% байтов ≠ N% токенов
  и ≠ N% стоимости задачи.

```bash
node summarize.mjs --out ./run1 --out ./run2 --out ./run3 > REPORT.md
```
