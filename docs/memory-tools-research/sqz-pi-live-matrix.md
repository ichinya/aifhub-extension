# Расход токенов в полных задачах Pi с SQZ

В снимке #186 только одна пара полных задач дала подтверждённый расход и для `off`, и для `sqz`. Во втором повторе исследования проекта A обычное чтение израсходовало **8 205 токенов**, SQZ — **12 119 токенов**. Это на 3 914 токенов больше с SQZ. Данных для общего вывода об экономии или выставленном счёте недостаточно. [Наблюдения по запускам](context-dedup-ai-tester/issue-186/snapshots/2026-11-25-windows-sqz-1.3.0/observations.json)

## Снимок #186 по полным задачам

Профиль Windows, Pi 1.6.0, OpenAI API, `gpt-6-luna / low`, SQZ 1.3.0. Для каждой задачи выполнено по три повтора в каждом режиме. Внутри повтора `off`, `aifhub` и `sqz` получили отдельные рабочие копии с одинаковым исходным хешем. Проверку результата прошли 24 из 27 запусков, три завершились ошибкой транспорта. Во всех трёх режимах задача решена в шести из девяти троек.

| Задача | Успешные тройки / запланировано | Пары с полным расходом `off` и `sqz` / запланировано | Медиана `off − sqz`, токены |
| --- | ---: | ---: | ---: |
| Исследование проекта A | 2/3 | 1/3 | −3 914 |
| Редактирование проекта A | 2/3 | 0/3 | нет данных |
| Редактирование проекта B | 2/3 | 0/3 | нет данных |

Сумма полной задачи берётся из `usage.totalTokens` по всем ходам сессии. В 14 из 27 сессий были ходы с ошибкой и неподтверждённым расходом. Такие сессии сохраняют исход задачи и известные счётчики, но не дают полного числа токенов. Показания стоимости из Pi и фактическое списание учитываются отдельно. [Агрегат с диапазонами и числом пар для каждой метрики](context-dedup-ai-tester/issue-186/snapshots/2026-11-25-windows-sqz-1.3.0/aggregate.json)

Для воспроизведения используйте обезличенные наблюдения, раздел `pins` и сборщик из репозитория. Он восстанавливает агрегат без модели и приватных исходников. Для нового живого замера оркестратор принимает manifest, профиль и новый выходной каталог. Сопоставимость требует тех же входных деревьев, хешей реализации и версии Pi. ## Исторический профиль Ornith

Следующие таблицы и наблюдения относятся к отдельной серии из 108 запусков. Её исходная сводка и построчные результаты доступны отдельно. [Сводка Ornith](../../benchmarks/pi-sqz-matrix/SUMMARY.md) · [Результаты прогонов](../../benchmarks/pi-sqz-matrix/REPORT.md)

- Агент: `pi` (print mode), провайдер `omniroute`, модель `la/ornith-1.5-35b-a3b`, thinking `low`.
- Read-агента перехватывается расширением и прогоняется через боевой
  `scripts/context-dedup.mjs`: тот же контракт `sqz compress --no-cache`,
  session ledger для точных повторов, fail-open, protected artifacts. Отдельного
  параллельного харнесса нет — тестируется интеграция как есть.
- 6 анонимизированных репозиториев (метки: `laravel-php`, `flutter-dart`,
  `unity-csharp`, `react-typescript`, `python-ts-monorepo`, `fastapi-react`)
  × 2 типа задач (research — исследование с точными фактами, exec — точечная правка)
  × 3 arms (`off`, `aifhub`, `sqz`) × 3 независимых прогона = **108 прогонов**.
- Изоляция: per-run state внутри проекта, уникальные session id, environment
  allowlist; после каждого exec-прогона рабочее дерево восстанавливается
  снапшотом (без `git reset`).
- Метрики: model-visible байты (per-read, extension) и **измеренный provider
  usage** из pi session files (не оценки). Токен-стоимость — `unavailable`
  (провайдер не отдаёт прайс модели).
- Точки входа: `benchmarks/pi-sqz-matrix/` (расширение, сценарии, оркестратор,
  summarizer). Сырые прогоны и бинарник sqz не публикуются; в репозитории —
  только агрегированные обезличенные результаты.

Пины: sqz `1.3.0`, `sqz.exe` SHA-256
`0C21ADFA0C67B6EB61EDD2B8B87C836AC2757A58D0D68D93376606E6CC75E76B`,
release archive SHA-256
`8243989670198FC0251404A330D843224D896FC6AAB1DE8233D73A0C1AA04158` —
совпадают с [sqz.md](sqz.md).

### Байты и токены в профиле Ornith

В четырёх из шести исследовательских задач Ornith средний расход входных и выходных токенов с SQZ вырос, хотя объём выдачи в байтах сократился. Отношение токенов всей задачи к байтам чтений включает другие ответы инструментов и ходы агента. Оно само по себе не устанавливает причину изменения расхода.

### Research-задачи: средний расход токенов на прогон (input+output, 3 прогона)

Средние включают все три строки с измеренным расходом на режим, в том числе неудачные ответы. Последняя колонка делит суммарную экономию байтов на суммарный вход по чтениям SQZ с известным размером. Для `unity-csharp` размер известен в двух из трёх запусков SQZ, для остальных меток — во всех трёх.

| профиль | off | aifhub | sqz | sqz к off | bytes saved (sqz) |
|---|---:|---:|---:|---|---:|
| laravel-php | 14 638 | 13 170 | **9 440** | **−36%** | 24.8% |
| fastapi-react | 14 151 | 12 654 | 13 537 | −4% (нейтрально) | 1.8% |
| react-typescript | 14 237 | 25 515 | 28 047 | **+97%** | 48.3% |
| python-ts-monorepo | 49 479 | 48 092 | 72 435 | **+46%** | 72.2% |
| unity-csharp | 28 000 | 42 961 | 63 426 | **+127%** | 68.2% |
| flutter-dart | 10 817 | 25 885 | 33 298 | **+208%** | 66.9% |

### Exec-задачи (точечные правки)

Средний расход входных и выходных токенов с SQZ вырос в пяти из шести задач. Для `laravel-php` обычный режим израсходовал в среднем 8 702 токена за три запуска. Два завершённых запуска SQZ из трёх дали в среднем 17 653 токена. Расход третьего неизвестен. Для `react-typescript` средние составили 10 951 и 17 030 токенов, для `flutter-dart` — 11 188 и 9 631 токен соответственно (по три запуска на режим).

### Дедупликация на живых сессиях

В исторической сводке по 108 запускам для AIFHub указано 0 точных повторов, для SQZ — 12 выдач по ссылке и 44 сжатых чтения. По строкам с доступной диагностикой предупреждений не зарегистрировано. [Историческая сводка](../../benchmarks/pi-sqz-matrix/SUMMARY.md)

## Сравнение по меткам в историческом профиле

Проценты показывают изменение среднего расхода токенов относительно `off`. В каждой ячейке по три запуска на режим, кроме `laravel-php / exec / sqz`, где расход известен для двух.

| метка | research | exec (точечные правки) | трактовка в этой серии |
|---|---|---|---|
| `laravel-php` | −36% | +103% | расход зависел от типа задачи |
| `fastapi-react` | −4% | +1% | небольшая разница средних |
| `react-typescript` | +97% | +56% | рост в обеих задачах |
| `python-ts-monorepo` | +46% | +72% | рост в обеих задачах |
| `unity-csharp` | +127% | +40% | рост в обеих задачах |
| `flutter-dart` | +208% | −14% (74.4% сжатия) | для research см. ограничения проверки качества |

Эти проценты сравнивают средние по режимам исследованной модели. У сценария `flutter-dart` были ошибки проверки ответов. Прямого живого замера сессии, переходящей между несколькими репозиториями, в этой серии не было. Для практического выбора режима проверьте исход задачи и сравните расход внутри одного повтора на той же модели и исходной копии.

## Качество и корректность

Из 108 запусков статус PASS получили 95, FAIL — 12, ERROR — один. В исследовательской задаче `flutter-dart` критерий ответа прошли 0/3 запусков `off`, 1/3 `aifhub` и 1/3 `sqz`. Поэтому средние по всем запускам этого задания описывают в том числе стоимость неудачных ответов. У строки ERROR (`laravel-php / exec / sqz`) счётчики отсутствуют.

## Ограничения

- 3 повторения на клетку, один агент, одна модель, один раннер: траектории
  агентов шумят, выводы опираются на агрегаты по профилям.
- Токены — measured provider usage; стоимость задачи — `unavailable`.
- Перехватывается только `read`; bash/grep-чтения агента не дедуплицируются.
- Одна платформа (Windows); linux-прогоны не выполнялись.
