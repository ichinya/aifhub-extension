### Каналы доставки

Runner остаётся `.mjs`-процессом и сохраняет floor Node `>=20.19.0`; этот floor описывает runner-процесс, а не инсталляционный канал. Начиная с OpenSpec 1.16.0 npm delivery channel requires Node `>=22.12.0` (npm-канал требует Node `>=22.12.0`, engines пакета). На хостах с Node 20–21 совместимые выборы: standalone-binary канал (без Node; собственная custody-цепочка, вне npm matrix) или оставаться на последнем npm-релизе совместимой линии 1.15.x. Detection маркирует это diagnostics-only полями `packageRequiresNode`/`packageNodeSupported`, выводимыми из версии CLI, а не из фактического `package.json` установленного CLI; канал установки detection не различает (`commandSource: explicit|project-local|path` ≠ канал), standalone binary не потребляет npm-engines.

## Executed matrix

Reproduction targets: [driver](../scripts/openspec-compatibility-live-smoke.mjs), [1.17 cases](../scripts/openspec-1-17-live-cases.mjs) и inherited 1.12 cases. В sandbox реализации на Windows / physical Node 24.13.0 (satisfies engines `>=22.12.0` exact CLI) выполнены прямые CLI-прогоны exact `bin/openspec.js`: targeted strict validate `runner-metrics` (5×WARNING >500 characters, **ноль scenario-step findings** — Scenario с GIVEN+THEN без WHEN не finding, GIVEN закрывает WHEN/GIVEN-сторону); агрегатный `validate --all --strict --json` до remediation (29 items, 40 WARNING = 22 Purpose placeholder + 18×>500-char, ноль новых классов) и после remediation (30 items, 18 WARNING — только >500-char, ноль placeholder, ноль новых классов); disposable-пробы на exact CLI: `+ **WHEN**`/`+ **THEN**` шаги распознаются парсером шагов (strict PASS, ноль findings); нечитаемый `openspec/config.yaml` — validate exit 1 (fail-closed), `list` продолжает exit 0; двухключевой `openspec/config.yaml` (project/title, без `schema`) принимается; strict validation change — `valid: true, issues: []`. Локальные parser probes (coverage-matrix и rules-compiler fallback) — задокументированный no-op: coverage толерирует closed requirement headings, inline fences инертны, секция DEPRECATED распознаётся; fallback DEPRECATED секцию не различает и closed/unspaced заголовки пропускает — в tracked-корпусе ноль таких строк вне archive, coverage не является синтаксической валидацией. **Полный live-driver на exact 1.17.0 не выполнен в sandbox** (этап оркестратора вне sandbox на Node >=22.12.0): живое поведение новых strict-классов в драйверных фикстурах, SHA-256 инвентарь внутри driver, bin/lifecycle и telemetry-off ветки — NOTRUN до оркестратора; deterministic- и direct-CLI прогоны не заменяют полный driver.

### Известный strict-warning долг (не регрессия этого change)

Агрегат exact CLI 1.17.0 после remediation содержит 18 WARNING класса «Requirement text is very long (>500 characters)» (класс 1.14.1, предсуществовал до #300): `runner-metrics` ×5, `generated-rules` ×2, `qa-manifest` ×2, `validation-gates` ×2, по одному в `coordination-dispatch`, `aif-analyze-bootstrap`, `host-delivery`, `openspec-cli-resolution`, `planning-workflow`, `prompt-localization`, `workflow-smoke-fixtures`. Владелец утвердил fallback-критерий remediation (2026-11-11): 0 placeholder-findings + 0 findings новых классов 1.16.x/1.17.0; расширение remediation на разбиение/сокращение normative-текста этих 18 требований отклонено как новый тип правки сверх bounded-границы варианта A; устранение — отдельное решение владельца. Агрегат из-за этого класса не полностью зелёный; ноль новых классов подтверждён.

## Reproduction and evidence limits

Подготовить exact npm package вне checkout, hash-verify tarball (sha1 `7dee0ac8…`, sha512 `D9MCbh1…`) до установки, установить с disabled lifecycle, затем выполнить:

```text
node scripts/openspec-compatibility-live-smoke.mjs <installed-package-root> <fission-ai-openspec-1.17.0.tgz>
npm run validate
npm test
openspec validate 300-adapt-openspec-1-17-0 --type change --strict --json --no-interactive --no-color
openspec validate --all --strict --json --no-interactive --no-color
```

PATH CLI при старте работы: 1.17.0 (локальная установка пользователя). Обновление пользовательской установки CLI и полный live-driver выполняет оркестратор вне sandbox на Node >=22.12.0. Direct CLI matrix этого audit использует checksum-bound `bin/openspec.js` exact 1.17.0 на physical Node 24.13.0; physical Node 18/20, standalone binaries, symlink privilege cases, hosted Ubuntu CI и publication не следует выводить из локального Windows запуска. Sandbox-категории NOTRUN этого change: полный live-driver на exact 1.17.0; физическое исполнение 1.17.0 на Node <22.12 (проверка маркера в реальном канале); standalone-квалификация; hosted CI. Receipts локальных прогонов сохранены рядом с рабочей областью реализации (`.custody-300/` вне checkout: aggregate-strict.json до/после remediation, probe-фикстуры, инвентарь). Локальный accepted-spec corpus существует; canonical OpenSpec paths ignored политикой этого extension-репозитория и не включены в package. Изменений extension.json.version, tags, push и публикации нет; assertion/gate ослабления для получения зелёного результата не вносились.
