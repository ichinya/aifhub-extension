# Пилот надёжности skills: калибровка

Полный пилот выполнен: **78 из 78 зарегистрированных попыток** имеют завершённый
host log и неизменяемый collector receipt. Это завершение пилота, а не доказательство
улучшения. Статус сравнительной квалификации —
`INCOMPLETE_NO_IMPROVEMENT_CLAIM`; ни один вариант не допущен к продвижению.

Машиночитаемые результаты: [pilot JSON](superpowers-skill-evaluation-pilot.json).
Методика и границы применения: [evaluation protocol](superpowers-skill-evaluation.md).
Основное измерение с тремя повторениями остаётся отдельной задачей.

## Что было запущено

- 39 cases, 9 вариантов, baseline/current, одно повторение каждого слота.
- Run ID: `0204d1e5-515c-4b9a-a85b-55267d2efb33`.
- Источник: HEAD `1a380ef76936ad17a0fd83b3586374cccd8b419d` и кандидат
  `c206375f72645e823dbada66deebf11a03fe2181bba12d29eb8c97582746671c`
  (693 файла в снимке реализации).
- Pi SDK, provider `zai-coding-cn`, model `glm-5.3-flash`, effort `max`.
  Зарегистрированная версия Pi — `0.84.4`; обнаруженный дрейф описан ниже.
- Свежая сессия для каждой попытки; четыре независимые пары одновременно,
  обе стороны пары последовательно в зарегистрированном порядке.
- Одинаковый лимит 300 секунд на ход. Запросы, эффективные определения четырёх
  инструментов и выбранные несекретные параметры provider request наблюдались
  непосредственно. Автоматические повторы и compaction отключены.
- Режим `synthetic-catalog`: локальная копия инструкций и fixtures, без полноценной
  установленной upstream-среды. PowerShell ограничен инструкцией и окружением,
  но это не изоляция средствами ОС.

Полные model-visible tool results, тексты ответов, изменения workspace и их хеши
сохранены локально у координатора. Скрытые рассуждения, credentials, сырые HTTP
заголовки и provider payloads не собирались. В публикуемом JSON отсутствуют сырые
ответы и приватные абсолютные пути.

## Наблюдения и пригодность

| Категория | Число |
| --- | ---: |
| Зарегистрировано / запущено / собрано | 78 / 78 / 78 |
| Допущено исходным collector по evidence отдельной попытки | 58 |
| Из них прошли все критерии | 21 |
| Из них не прошли хотя бы один критерий | 37 |
| Не допущено; результат `null` | 20 |
| Тайм-ауты | 11 |
| Ошибка model response без тайм-аута | 2 |
| Несовпадение версии Pi при начале попытки | 7 |

Последние три строки разбивают 20 недопущенных попыток. В JSON `modelError = 3`
включает одну попытку, также завершившуюся тайм-аутом; для непересекающегося подсчёта
нужен `nonTimeoutModelError = 2`. Ожидаемый содержательный ответ `incomplete`
(например, отсутствует prerequisite) может пройти сценарий. Прерванная сессия с
неполным evidence не превращается в такой успешный ответ.

Сохранённые `eligible`, `pass` и `comparison.variants` — результат исходного
collector. Они не учитывают все обнаруженные затем ограничения эксперимента.
В частности, `comparison` содержит предварительные `improvement`, `regression`
и `mixed` для некоторых групп. **Ни один из этих ярлыков не является выводом об
эффекте кандидата:** весь пилот помечен `comparativeQualification.eligible = false`.
Не следует складывать эти группы в общий показатель качества skills.

## Что показала калибровка

| ID | Наблюдение | Следствие для следующего измерения |
| --- | --- | --- |
| CAL-1 | Нормализатор ошибочно счёл `String.Substring` при выводе пути действием до загрузки skill; исходная оценка слота 3 сохранена. | Зафиксировать исправленный PowerShell AST classifier до запуска; слот 3 не использовать для вывода об эффекте. |
| CAL-2 | Общее требование отчёта конфликтует с оригинальными заданиями «одна фраза»; затронут и `mode-discussion`. | Явно сохранить приоритет формата оригинального запроса в новой версии TASK. |
| CAL-3 | Пятиминутный лимит прервал planning, bootstrap и поиск pollution. | Откалибровать больший одинаковый лимит, зарегистрировать новый settings hash. |
| CAL-4 | Ошибка model response возникала и после HTTP 200; сохранённых данных недостаточно для установления причины. | Сохранять ограниченную категорию ошибки и хеш сообщения без его приватного содержимого. |
| CAL-5 | Второй ход `explore-to-plan` сформулирован условно, а runner планирует безусловную доставку. | В новой версии явно определить обязательный follow-up либо проверяемое условие его доставки. |
| CAL-6 | Fixtures не содержат установленные CLI и upstream templates, на которые ссылаются инструкции. | Сохранить ограничение synthetic-catalog; эти данные не доказывают installed-host compatibility. |
| CAL-7 | Пустой write allowlist местами неочевиден из запроса; правильный ответ сопровождается запрещённым trace, summary или новым тестом. | Сделать разрешённые изменения видимыми как условия задания, не раскрывая ожидаемый skill и рубрику. |
| CAL-8 | Текущая схема требует assistant final и исключает даже полностью наблюдавшийся terminal error. | Не ослаблять evidence gate задним числом. Возможное различение terminal failure и неполного evidence требует отдельной схемы и отрицательных проверок. |
| CAL-9 | Review fixtures не содержат точную upstream-схему gate; большинство ответов выдумывают поля, один корректно сообщает об отсутствии контракта. | Уточнить сценарий missing prerequisite или предоставить ограниченный действующий контракт в новой версии; продвижение composition пока запрещено. |
| CAL-10 | Общая установка Pi обновилась с `0.84.4` до `0.85.1` во время пилота. | Следующий run должен загружать полный локальный снимок SDK и зависимостей с закреплённым digest. |

CAL-10 непосредственно обнаружен в стартовых записях слотов 71–77. Это наблюдение
версии package metadata, а не доказательство, что все модули этих сессий исполнялись
из новой версии: runner импортировал SDK раньше. Стартовые записи предыдущих
попыток также не доказывают неизменность файлов runtime на всём интервале исполнения.
Поэтому сохранение раннего `eligible: true` не разрешает причинное сравнение.

Нормализатор развивался версиями v2–v8; старые логи, grades и receipts не
перезаписывались. Хеши калибровочных записей перечислены в JSON. Shell exit и
наблюдаемый native Node/npm exit различаются: успешное завершение PowerShell не
считается доказательством успешного теста. Неоднозначные команды требуют проверки
по полному tool result.

Помимо дефектов стенда наблюдались реальные полезные и ошибочные действия: RED/GREEN
для точечной правки, обоснованное отклонение вредного remedy, восстановление
потерянной опции на границе вызова, лишние загрузки skills, выдуманные gate fields,
неверное толкование pollution trials и сравнение восстановления загрузки с
неполученным job ID. Такие примеры помогают уточнять проверку поведения; сами по
себе они не подтверждают преимущество всего пакета.

## Границы оценки

Координатор сверял ответы с исходными fixtures, действиями и diff; исполняемые
behavior probes проверяли результат независимо от заявления модели. Для
discovery, composition и visual utility применялась ручная семантическая рубрика.
Оценка не была слепой, отдельного второго оценщика не было. Утверждения во всех
финальных ответах проверены; промежуточные тексты перед tool calls не прошли
исчерпывающую проверку claims. Это ограничение нужно устранить до основного замера.

Visual cases — проверка полезности предложенного сравнения по заданной рубрике,
а не UX-исследование с пользователями. Расход и скорость не сравнивались.
Linux и другие модели не запускались. Пилот не заменяет независимый review
окончательного diff и владельческий `$aif-verify`.

Перед основным измерением нужны новая версия условий, неподвижный runtime,
зафиксированный observer и повторная проверка evidence gates. Все 234 слота
основной матрицы должны быть зарегистрированы до запуска; неудачные cases пилота
не исключаются из неё по результату.
