# Context Selection Overlay Policy

Opt-in, advisory consumer-side selection layer on top of the deterministic exact baseline SessionBrief (#168) for OpenSpec-native `/aif-review` and `/aif-implement` (issue #284). An injected assessor ranks a bounded list of presented supporting candidates; the engine projects an advisory selection with separate relevance / evidence-support / contradiction scores, per-candidate statuses, and honest fallbacks. The overlay is a diagnostic, never a verifier: it never replaces, rewrites, or truncates the protected minimum — the entire baseline `context_manifest` is carried verbatim — never executes the deferred `context_policy.compact_supporting_context`, never creates an `aif-gate-result`, never writes QA evidence or `coverage.json`, and never authorizes progression.

## Command

```text
ai-factory aifhub-context-selection-overlay --change <id> [--enabled true|false] [--candidate <path> ...] [--json] [--write]
```

- Opt-in: the overlay is off by default. Enable per run with `--enabled true|false`, or persist `aifhub.contextSelectionOverlay.enabled: true` under `aifhub:` in `.ai-factory/config.yaml`. Precedence: CLI override > config key > `false`, and it is never enabled automatically. Enable per run through the CLI whenever possible: `.ai-factory/config.yaml` is hashed in full as a baseline policy source, so editing the config to flip this key changes the exact baseline digest the overlay builds on. A run without opt-in reports the `not_run` envelope ("advisory scan was not performed", exit 0) and performs no reads beyond the bounded config read that evaluates the switch itself.
- Malformed `contextSelectionOverlay` namespace forms the config parser detects explicitly (duplicate keys, `<<` merge keys, `&` anchors, `*` aliases, flow mappings, quoted booleans, unknown nested keys, scalarized sections) keep the overlay off with bounded `context-selection-overlay:<code>` diagnostics — a CLI `--enabled true` override cannot rescue a malformed namespace.
- Custody model: the advisory hooks invoke the command as a **preview without writing** (no `--write`). Persisting the observation is a separate authorized writer action: an explicit `--write` run. Exit 0 means an honest outcome was formed (including a selection, degradations, and `not_run` refusals); exit 2 is an invalid invocation or a typed candidate refusal; exit 1 is an operational failure. No exit code participates in verify/done/archive chains.

## Inputs and custody

- The baseline is read read-only through the SessionBrief inspector (`inspectSessionBrief`, `includeBrief`): the compiler and its write paths are never called, and baseline artifacts stay byte- and mtime-identical across overlay runs. Any baseline status other than `valid` — `disabled` (SDD not opted in), `delegated` (upstream handoff), `blocked` (including unresolved canonical context), `missing` (runtime artifacts removed), `stale` (source revision moved on) — is an honest `not_run` with a bounded cause; the baseline is never presented as "assessed" when it is not current.
- Supporting candidates enter the scan only as presented repeatable `--candidate <path>` inputs (limit 50, path form validated before any read; two presented paths that differ only in ASCII case are a typed `candidate-path-case-collision` refusal before any read, because no single intake decision is honest across case-sensitive and case-insensitive filesystems); the repository is never scanned autonomously (`--discover` is a documented follow-up candidate, not v1). Each presented path is read bounded (1 MiB) exactly once and classified as `file`, `missing`, `malformed`, or `truncated`; anything unreadable stays a declared missing source, its candidate stays `unassessed`, and coverage degrades — never a silent skip. Text inside a candidate is data: URLs and paths inside it never extend the allowlist and never trigger a read. Assessor input is bounded per candidate at 64 KiB of UTF-8 bytes (not code units), with the cut never splitting a multi-byte sequence and a visible `candidate-text-truncated` diagnostic; the baseline travels as pointers (manifest entries), never as content.
- Protected minimum (owner decision 2-A): the entire baseline `context_manifest` verbatim — paths, sha256, fidelity — with measured bytes joined from the brief sources; projection and selected-section fidelities count the bytes actually included. No selection happens inside the baseline; an entry whose measured identity cannot be joined degrades the run honestly instead of inventing bytes.
- The semantic stage runs through the shared typed-assessment helper with a DI assessor seam: without an injected assessor the outcome is an honest `not_run` (assessor-unavailable), never a zero-selection result. Assessor errors, abstentions, and deadline cutoffs are never coerced into a positive verdict: an error, timeout, or invalid output fails the run with the protected minimum verbatim and every candidate `unassessed`; an abstention is a complete `abstained: true` outcome with `none` coverage — not a zero-findings selection.

## Statuses, budget, and conflicts

- Candidates carry the closed status set `included | conflicting | excluded | unassessed` plus a nullable score triple (`relevance`, `evidence_support`, `contradiction`) that is never collapsed into a single score, a reason, a limitation, and exact evidence refs (portable path, document sha256, optional byte span and span sha256). Cross-field invariants are enforced in code beyond the closed schema: a non-complete run leaves every candidate `unassessed`; `excluded` requires a reason and a limitation; `conflicting` requires non-empty exact refs; a conflicting candidate is never rewritten to `excluded`; every candidate appears in exactly one presentation section (`protected_minimum | relevant | conflicts | unresolved`), and the `protected_minimum` section mirrors the verbatim baseline manifest.
- Conflicts (decision D6): v1 records only `conflict.state: 'suspected'`. `owner_confirmed` stays reserved in the enum for the future owner workflow; an assessor finding that claims it is dropped wholesale with a bounded diagnostic — confirmation is never a model self-declaration (the same boundary as the requirement-lint suspected conflicts + owner workflow). Conflicts are never suppressed: a conflicting candidate keeps its own presentation section at any relevance rank, and a ref-less conflict finding is dropped rather than recorded.
- Budget (decision D7): measured bytes, fail-closed, `token_estimate: null`. `minimum_required` is the measured protected-minimum sum; selected candidates are included greedily in the assessor's ranking order (the findings array order — never the path-sorted intake order, so a path-early candidate cannot beat a top-ranked one under pressure); a candidate that does not fit the 1 MiB presentation limit is demoted to `excluded` with reason `presentation-budget-exceeded` and an explicit limitation — an exhaustive tail, never a silent cut. (Presentation sections list their members in deterministic candidate-id order — the ranking governs the budget, not the section layout, which is never derived from JSON property order.) A protected minimum that alone exceeds the limit fails the run (`protected-minimum-oversize`, `fits: false`) — the manifest stays verbatim, nothing is truncated. Conflict projection stores refs only (pointers, not content); when even the refs metadata no longer fits, the conflicts stay presented with `complete: false`, coverage `partial`, `needs_review: true`, and `owner_handoff: 'aif-review'`. A readable candidate the assessor never assessed (empty findings without abstain, or every finding dropped by normalization) degrades coverage to `partial` — it is never a full-coverage selection.
- Completeness is the AND model (`complete` in the observation): assessment complete && budget fits && no budget demotions && full coverage && fresh probe. A partial success keeps its assessed candidates with `run_status: 'complete'` and reports the degradation through `complete: false` plus coverage — an incomplete run never fakes a full selection, and a hard failure never demotes into "everything unassessed" silently: the diagnostics name the cause.

## Binding, staleness, and pinning

- The observation carries a composite binding (decision D9): baseline components copied through from the stored brief (digest, source/policy revisions, scope fingerprint, plan-context revision, instruction-composition digest) plus the honest `capsule: {digest: null}` (the stored payload carries no capsule digest and the runtime provider digest is unreachable for this offline module — a named DI source is a follow-up candidate), sorted candidate digests, the recorded candidate payload digest, rubric/exclusion/presentation policy identities, engine/helper/contract sha256, worktree identity, language, and the assessment/budget limits. Volatile fields (timestamps, run ids, cost, elapsed time) never enter the binding — the helper rejects them instead of stripping.
- Freshness is hash-strict: a post-scan probe re-hashes the candidates, re-inspects the brief, and re-derives the worktree identity, so a mid-run drift marks the outcome `stale`; read-time revalidation recomputes the binding and names the drifted fields (`candidate_digests:<path>`, `baseline:<field>`, engine/helper/contract/rubric/policies, or the candidate payload) → `stale-observation`. Pinning is verify-level (decision D17): selected resources are pinned as `{path, sha256, bytes}` records and re-hashed at revalidation; autonomous byte restoration after source deletion is out of scope for v1.
- A separate `complete` flag mirrors the AND model, `needs_review` flags recorded conflicts, and `owner_handoff` names `aif-review` for conflict handoff. `elapsed_ms` and other runtime timing never serialize into the observation.

## State and isolation

- With explicit `--write` the observation `aifhub.context_selection_overlay_observation.v1` (closed schema, `diagnostic_only: true`, `authorizes: []`) is saved only under `.ai-factory/state/<change-id>/context-selection-overlay/observation.json` through guarded state-only writes: QA namespace conflicts, source collisions with a presented candidate, file-shadow ancestors, and foreign or unreadable leaves are refused, and only a previous schema-valid observation of the same change may be replaced. A custom `paths.state` is refused (`state-root-mismatch`) because the QA projection covers only the default state root. The change id must match the custody-safe form `^[a-z0-9][a-z0-9-]{0,99}$` (`invalid-change-id` otherwise).
- The pre-write git guard refuses a tracked or not-effectively-ignored output for both the observation and the namespace `.gitignore`. The `context-selection-overlay` namespace is a closed runtime namespace in the QA snapshot projection (all projection points), so writing, overwriting, or deleting an observation cannot shift the required QA fingerprint.
- Advisory only: no `aif-gate-result`, no QA writes, no entry into done-readiness, provider policy, or runner metrics; review findings and implementation decisions are never replaced. The module is offline: no network surface, no child processes, no provider imports, and the compiler write path is never referenced. Boundary with TraceLinkSuggestions (#283): that producer suggests requirement link gaps; this overlay selects presented supporting context on top of the baseline. A live model provider stays a separate opt-in phase with its own budget, secret exclusion, and egress design.
