# RTK: A/B на связанных репозиториях

На 2026-09-05 выполнены **24 основных запуска**: четыре сценария, две группы,
три повторения. Baseline прошёл **11/12**, RTK — **12/12**. Суммарный расход
токенов уменьшился на **15,8%**, время — на **1,2%**. Это ограниченный результат
на одном наборе связанных репозиториев; решение о рекомендации RTK остаётся
`reject_defer` из-за ранее выявленных проблем хранения данных и невыполненного
строгого критерия полного прохождения обеих групп.

RTK сокращает вывод команд перед передачей модели. Здесь ai-tester создаёт копии
и запускает сценарии через ACP; Pi исполняет задания моделью
`omniroute/la/ornith-1.5-35b-a3b` с thinking `low`. В группе RTK подключён
неизменённый официальный Pi extension версии `0.48.0`. Для обоих вариантов
одинаково доступны полное чтение исходников и повтор команды с `raw` после её
обычного выполнения. Поэтому измеряется поведение агента с компрессией и
восстановлением вывода, включая стоимость этих повторов.

## Репозитории и сценарии

Исходные имена и соответствие меток локальным путям не включены в отчёт,
сценарии или JSON. Использованы копии чистых Git-коммитов; исходники не менялись.

| Метка | Роль в проверке | Исходный commit |
|---|---|---|
| repo-01 | TypeScript: потребитель данных и отображение статуса | `fe51e04561110db5fd8ca970c7c1b76c4b5cd80e` |
| repo-02 | PHP: производитель JSON и enum статусов | `65c56867d658c281e06d677bc9b4ee09cec70132` |
| repo-05 | Python: прокси ответов и обработка ошибок HTTP | `025483e3298bbebce3e6bcfba74978f0f6a2a24d` |

| Сценарий | Что проверяется |
|---|---|
| contract-review | Переименование `status` в `state` у производителя, несовместимость с потребителем и передача поля прокси без переименования |
| security-review | Добавление `log` в краткий ответ и передача upstream-тела для 401/403/404/500; правильный владелец каждой проблемы, отсутствие лишней находки в repo-01 |
| multi-diagnostics | Все 12 пар actual/expected и их владельцы при одинаковых именах тестовых файлов в трёх репозиториях |
| coordinated-fix | Согласованное исправление трёх исходных файлов с сохранением корректного поведения вне видимых тестов |

Дефекты внесены **специально в тестовые копии**. Это не найденные ошибки исходных
проектов. В review-сценариях дополнительно изменены 64 строки служебных заметок
в каждом репозитории: это управляемый шум для проверки фильтрации diff.
Рабочие тесты исполняют настоящий TS helper, PHP enum и Python HTTP proxy;
сетевые ответы замоканы. Полные приложения и их развёртывание не запускались.

## Основной результат

| Сценарий | Baseline PASS | RTK PASS | Токены baseline | Токены RTK | Экономия RTK |
|---|---:|---:|---:|---:|---:|
| contract-review | 3/3 | 3/3 | 89 548 | 67 348 | 24,8% |
| security-review | 2/3 | 3/3 | 86 150 | 50 169 | 41,8% |
| multi-diagnostics | 3/3 | 3/3 | 41 412 | 45 768 | −10,5% |
| coordinated-fix | 3/3 | 3/3 | 209 433 | 195 982 | 6,4% |
| **Всего** | **11/12** | **12/12** | **426 543** | **359 267** | **15,8%** |

Один baseline-ответ в security-review перечислил 401/403/404, но пропустил 500.
Это содержательная ошибка, сохранённая в основной выборке. Инфраструктурных
ошибок или неполных основных попыток не было; повторов ради улучшения результата
не выполнялось. Во всех 12 RTK-попытках реально выполнялись сжатые команды.

Время основных попыток с последующей скрытой проверкой: baseline **363,5 с**,
RTK **359,1 с**. Это wall time всего запуска, а не чистая задержка модели.
Учтена сумма `input + output + cacheRead + cacheWrite` всех assistant messages;
кешированные токены в этой серии равны нулю. Нулевые ACP-счётчики ai-tester и
нулевые цены в конфигурации провайдера не использованы для оценки стоимости.

Токены уменьшились в **7/12 пар**, медианная экономия по парам — **25,0%**.
Без самой дорогой baseline-пары общая экономия составляет **7,9%**.
В третьем повторении coordinated-fix RTK потратил 110 684 токена против 47 477:
разброс заметен даже при одинаковых заданиях. Это не стабильная оценка экономии
для произвольного мультирепозитория и не доказательство улучшения качества модели.

Порог пользы был задан до основной серии: минимум 15% экономии, не более 10%
роста времени и положительная медиана. Он выполнен. Отдельный строгий критерий
качества требовал полного прохождения **обеих** групп во всех парах и не выполнен
из-за baseline-ошибки. При этом все проверки RTK в этой серии прошли; смешивать
этот результат с результатом предыдущего эксперимента нельзя.

## Компрессия и полные диагностические данные

Прямой probe подтвердил правильную маршрутизацию каждой команды
`rtk git -C repo-* diff`: её stdout побайтно совпадает с `rtk git diff` внутри
соответствующего репозитория. Сжатие действительно происходит, это не простой
пропуск исходного вывода.

| Репозиторий | Raw diff, байт | RTK diff, байт |
|---|---:|---:|
| repo-01 | 6 195 | 4 998 |
| repo-02 | 6 980 | 5 648 |
| repo-05 | 6 195 | 4 998 |

В отдельном probe pytest stdout уменьшился с **12 098 до 2 726 байт**, но
содержал только **10 из 12** уникальных наборов `owner/case` с операндами.
Оба процесса вернули exit 1. Во всех трёх основных RTK-попытках
multi-diagnostics модель запросила raw-повтор и затем правильно восстановила
все 12 результатов. Именно поэтому эта группа оказалась дороже baseline.
Размеры stdout зависят в том числе от строки времени pytest; это байты, не токены.

Всего выполнено **47 сжатых команд**, **5 raw-повторов** у RTK и **2** у baseline.
Объём всех tool responses, включая полные чтения исходников и повторные команды,
уменьшился только на **9,8%**: с 315 494 до 284 493 байт. Экономию отдельного
stdout нельзя переносить на весь контекст агента.

## Воспроизводимость и границы проверки

Версии: ai-tester `1.2.0`, Pi `0.84.4`, pi-acp `0.0.33`, RTK `0.48.0`,
Node `24.13.0`, PHP `8.4.1`, Python `3.13.5`, pytest `8.4.2`, httpx `0.28.1`.
Полные хеши бинарников, расширения, runner и commit копий записаны в JSON.
Модель идентифицирована настройкой провайдера; соответствие alias конкретным
весам независимо не подтверждалось.

Каждая попытка использовала свежую копию всех трёх репозиториев с отдельными
`.git`, одинаковый prompt внутри пары и лимит 30 tool calls. Порядок групп
чередовался по сценарию и повторению; фиксированный seed модели не задавался.
RTK tee и telemetry отключены; локальная БД RTK направлена во временный каталог.
Оригинальные remotes, `.env` и файлы с перечисленными credential-именами не
переносились. Это фильтрация имён, а не доказательство отсутствия секретов
в произвольном исходном тексте.

Положительный контроль на неизменённых исходниках прошёл. Внесённые runtime
дефекты до запуска модели дали ровно 12 ошибок. После coordinated-fix скрытый
grader проверил 12 контрактных случаев, queued/unknown badges, сохранность
label, успешного JSON, тела 409 и кодов ошибок. Все шесть исправлений прошли
эти проверки. Тестовые файлы в sandbox не изменены; изменения ограничены тремя
разрешёнными исходными файлами. Allowlist инструментов не является OS sandbox
для произвольного кода внутри изменённых файлов.

Дополнительно выполнены два connectivity smoke и четыре pilot-запуска; их
агрегаты сохранены отдельно и не включены в основное сравнение. После pilot
исправлен протокол fixture: внесённые дефекты coordinated-fix закоммичены
в каждой временной копии, чтобы восстановление исходной логики оставляло
видимый diff. Это сделано до всех 24 основных попыток.

Аудит сверяет исходные коммиты и чистоту рабочих деревьев, байты snapshot
с Git-объектами, головы всех sandbox-репозиториев, разрешённую область изменений,
неизменность тестов, счётчики sidecar и хеши inference harness.
Сырые ответы, исходники и соответствие меток путям в публикуемые файлы не входят.
Сверка прошла для всех 24 попыток и 522 исходных файлов в snapshot.
`npm run validate`, `git diff --check` и семь проверок grader/guard/JSON extraction
прошли. Полный `npm test` в рамках этой серии не запускался.

Очистка временного каталога этой серии **не выполнена**: автоматическая проверка
разрешений отклонила подготовленное удаление с причиной `blocked by policy`.
Копии, сырые журналы, локальные БД RTK и приватное соответствие меток путям
остались во временном каталоге. Они не добавлены в репозиторий. Сохранённый
`retention` в JSON явно отмечает это исключение из aggregate-only retention;
обезличивание опубликованных результатов не означает удаления локальных данных.

Результат относится к этим сценариям на одном наборе связанных репозиториев.
Он не закрывает ранее обнаруженные [privacy blockers RTK](README.md) и не
проверяет полный цикл `/aif-plan → /aif-implement → /aif-verify → /aif-fix`.
